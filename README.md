# Web Games launcher

A static PWA that lists my games, downloads each one from a (private) GitHub repo using an access token entered on the device, caches it for offline play, and lets every game be installed to the home screen on its own. Nothing secret is in this repo — the token lives only in each device's `localStorage`.

## Hosting

GitHub Pages → Settings → Pages → deploy from `main` / root. Then open `https://<user>.github.io/webgames/` on the phone and use **Share → Add to Home Screen** (iOS) or **Install app** (Android).

## Using it

1. Open the launcher → ⚙ Settings → paste a GitHub token → **Save & sync**.
   Use a fine-grained token with **Contents: read-only** on just the game repos.
2. Tap a game for its install page, then Play. First launch downloads it; afterwards it runs offline and quietly checks for updates (ETag-based, so unchanged games cost almost nothing).
3. Tapping a game's icon opens its install page (`install.html?game=<id>`) with Add-to-Home-Screen instructions (and an Install button on Android/Chrome). The installed app starts at `play.html?game=<id>` with its own name and icon.
   An installed app gets the token from its install link (see Notes).

## Adding a game

1. The game lives in a (private) GitHub repo. It can be one HTML file or a whole app (ES modules, JSON, fonts, images...) — anything that runs from relative paths when served statically.
2. Add an icon: `python3 tools/make-icon.py games/my-game/icon-512.png "MG" "#4ea1e8"`, or copy the 512×512 icon (plus a 512 maskable and a 180×180 `apple-touch-icon` if you have them) into `games/my-game/`.
3. Add an entry to `games.json`:
   ```json
   {
     "id": "my-game",
     "title": "My Game",
     "shortName": "MyGame",
     "description": "One line shown on the card.",
     "repo": "owner/private-repo",
     "ref": "main",
     "entry": "index.html",
     "include": ["index.html", "src/", "data/"],
     "icon": "games/my-game/icon-512.png",
     "maskableIcon": "games/my-game/icon-maskable-512.png",
     "appleIcon": "games/my-game/apple-touch-icon.png",
     "background": "#10131a",
     "theme": "#10131a",
     "orientation": "any"
   }
   ```
   `entry` (default `index.html`), `include` (default: whole repo) and `exclude` (extra paths to skip; `.git*`, `.github/`, `node_modules/` are always skipped) take file paths or `dir/` prefixes. Only list what the game needs at runtime — tests, docs and art galleries just waste phone storage. `ref` is a branch or tag. Icon fields besides `icon`, and the colours, are optional.
4. Commit and push; the launcher picks it up next time it's opened online.

## How games are served

- Tapping a game opens `install.html?game=<id>` (install instructions); **Play** / the installed icon opens `play.html?game=<id>`, which syncs the repo and then navigates to `g/<id>/<entry>`.
- Sync reads the repo tree through the GitHub API (one conditional request, so an unchanged game costs almost nothing), downloads only files whose git SHA changed, and stores them in the Cache API. A failed update never leaves a half-updated game.
- `sw.js` answers requests under `g/<id>/…` from that cache, so relative imports and `fetch`es just work, and works offline. It also rewrites the entry HTML to (a) namespace `localStorage` per game (`wg:<id>:`) and (b) use the manifest, icon and title from `games.json` instead of the game's own.
- A game's own service worker / `manifest.webmanifest` are ignored (its `sw.js` is never served as a worker: it's outside our scope). Games must not rely on being served from the site root or on their own deploy pipeline.

## Notes

- The launcher shell is cached by a service worker; bump `CACHE` in `sw.js` if you change the shell and want phones to pick it up immediately.
- An installed home-screen app has its own storage on iOS, so it can't see the launcher's token. To avoid pasting it again, the install page puts the token into the installed app's start URL (`play.html?game=<id>&k=<token>`); on first launch the app saves it and strips it from the address. Settings shows the token in plain text with a Copy button for sharing.
- `manifest/<id>.webmanifest` is generated by the service worker from `games.json`.
- Every page uses the opaque `black` iOS status bar (`apple-mobile-web-app-status-bar-style`), and the service worker forces it onto each game's HTML too (override per game with `"statusBar"` in `games.json`). iOS reads it when an app is added to the Home Screen, so delete and re-add an installed icon after a change.
