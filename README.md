# Web Games launcher

A static PWA that lists my games, downloads each one from a (private) GitHub repo using an access token entered on the device, caches it for offline play, and lets every game be installed to the home screen on its own. Nothing secret is in this repo — the token lives only in each device's `localStorage`.

## Hosting

GitHub Pages → Settings → Pages → deploy from `main` / root. Then open `https://<user>.github.io/webgames/` on the phone and use **Share → Add to Home Screen** (iOS) or **Install app** (Android).

## Using it

1. Open the launcher → ⚙ Settings → paste a GitHub token → **Save & sync**.
   Use a fine-grained token with **Contents: read-only** on just the game repos.
2. Tap a game to play. First launch downloads it; afterwards it runs offline and quietly checks for updates (ETag-based, so unchanged games cost almost nothing). Tap the small handle at the top centre while playing for the menu (home / check for update / restart).
3. Tapping a game's icon opens its install page (`install.html?game=<id>`) with Add-to-Home-Screen instructions (and an Install button on Android/Chrome). The installed app starts at `play.html?game=<id>` with its own name and icon.
   Note: an installed home-screen app has its own storage (especially on iOS), so it asks for the token once on first launch.

## Adding a game

1. Put a self-contained HTML file in a (private) repo.
2. Make an icon (512×512 PNG, keep important art inside the central 80%):
   ```
   python3 tools/make-icon.py games/my-game/icon.png "MG" "#4ea1e8"
   ```
   or drop your own PNG there.
3. Add an entry to `games.json`:
   ```json
   {
     "games": [
       {
         "id": "my-game",
         "title": "My Game",
         "shortName": "MyGame",
         "description": "One line shown on the card.",
         "repo": "owner/private-repo",
         "path": "index.html",
         "ref": "main",
         "icon": "games/my-game/icon.png",
         "background": "#10131a",
         "theme": "#10131a",
         "orientation": "any"
       }
     ]
   }
   ```
   `ref` (branch/tag) and `path` are optional (default: repo default branch, `index.html`). `orientation` can be `portrait`, `landscape` or `any`.
4. Commit and push; the launcher picks up the change next time it's opened online.

## Notes

- Games run in a sandboxed same-origin iframe. `localStorage` is namespaced per game (`wg:<id>:`), so saves don't collide.
- Single-file games only for now (everything inline, no relative asset requests).
- The launcher shell is cached by a service worker; bump `CACHE` in `sw.js` if you change the shell and want it picked up immediately.
- `manifest/<id>.webmanifest` is generated by the service worker from `games.json`, so there are no per-game manifest files to maintain.
